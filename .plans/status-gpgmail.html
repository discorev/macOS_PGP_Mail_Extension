Found during step 6

Two bugs only Mail could show

Extension crashed on every load

Swift 6 inferred main-actor isolation from MailKit's protocols, but Mail creates the extension on an XPC queue, so MailExtension.init() trapped (8 crash reports). Mail showed raw armour and failed draft saves with "error occurred while trying to encrypt". Fix: the principal and handler are nonisolated; only the view-controller methods are @MainActor.

Mail wants LF back, not CRLF

Mail hands the extension CRLF, but for decoded mail returned with CRLF it shows "This message has no content". The first test send also crashed Mail (-[__NSSetM addObject:]: nil) right after encode returned CRLF. Fix: the MailKit edge converts everything handed back to Mail to LF, as your 2021 code did. The core stays CRLF. The second send went through with no crash.

Deviations and decisions

  • Your calls during the run: encrypt to any imported key (--trust-model always), and drop the key counts from the setup screen. The host app stays sandboxed.
  • Plan A4, amended by evidence: the core is CRLF-only, and the MailKit edge converts CRLF in and LF out (not CRLF both ways).
  • Mail doesn't run security extensions on .eml files opened from disk. Only messages in mailboxes go through the decoder.
  • The pgpmime-signed fixture was signed over the boundary CRLF. Fixed so the decoder stays strictly RFC 3156, with no retry heuristic.
  • Steps 3 and 4 ran as one agent with two commits, because the core was rewritten rather than moved.
  • Mail calls encode twice per send, and decodedMessage for every message you view. Non-PGP mail gets nil back quickly.
